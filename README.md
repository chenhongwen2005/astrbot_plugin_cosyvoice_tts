# CosyVoice2 方言语音

AstrBot 插件。把一段 3–10 秒的语音发给机器人当音色，之后它就能用这个音色、按你指定的方言把文字念出来——11 种方言，默认走「自然语言控制」模式。

推理全部转发到 ModelScope 上的公开创空间 [`iic/CosyVoice2-0.5B`](https://www.modelscope.cn/studios/iic/CosyVoice2-0.5B)，**本机不需要显卡、不需要下载模型权重**，装好插件填一段参考音频就能出声。

| | |
|---|---|
| 方言 | 广东（粤语）、闽南、四川、东北、陕西、山西、上海、天津、山东、宁夏、甘肃 |
| 模式 | 自然语言控制（默认，不需要参考文字）／3s 极速复刻 |
| 依赖 | 无。只用 AstrBot 自带的 aiohttp，**不需要 `gradio_client`** |
| 输出 | 24 kHz 单声道 wav，直接当语音消息发 |
| 接入方式 | `/语音` 指令 + 注册成 AstrBot 原生 TTS Provider |

---

## 1. 三分钟上手

1. **装插件**：把整个目录放进 `data/plugins/`，重启 AstrBot。日志里应出现
   `[cosyvoice] v1.0.0 已加载｜方言 11 种｜Provider 已注册`。
2. **给音色**：私聊机器人**发一段语音**（3–10 秒，说一句完整的话，只发语音别带文字）。
   它会回你：已记下这个音色 · 2.8s · 22kHz · 参考文字「……」。
3. **让它说**：`/语音 今天天气不错，我们出去走走吧。`
4. **换方言**：`/语音 方言 四川`，再 `/语音 示例` 听一句本地话。

想让机器人**正常回复就自动带方言语音**，见第 6 节。

## 2. 指令手册

| 指令 | 作用 |
|---|---|
| `/语音 <文本>` | 用当前音色 + 当前方言朗读。文本原样念，不会当成参数 |
| `/语音 方言` | 列出 11 种方言，▶ 标出当前的 |
| `/语音 方言 四川` | 切换方言。别名都认：`粤语`/`成都话`/`兰州话`/`东北腔`… |
| `/语音 方言 关` | 关掉方言，回到标准话 + 纯音色 |
| `/语音 音色` | 看当前音色（来源、时长、参考文字、文件路径） |
| `/语音 音色 换` | 进入等待状态，接下来发的那段语音用来换音色 |
| `/语音 音色 文字 <文字>` | 手工补/改参考文字（复刻模式需要它和音频内容对得上） |
| `/语音 音色 全局` | 把本会话音色设为全局默认，供原生 TTS 使用 |
| `/语音 音色 清除` | 删掉本会话的音色 |
| `/语音 指令 <自然语言>` | 追加修饰，如 `/语音 指令 语速慢一点` |
| `/语音 指令 清空` | 清掉修饰；清过之后不再回落到配置里的默认修饰 |
| `/语音 复刻 <文本>` | 这一次用 3s 极速复刻模式，不切方言 |
| `/语音 示例` | 用当前方言念一句该方言的台词 |
| `/语音 设置` | 一次性看当前所有设置 |
| `/语音 状态` | 探活：接口地址、版本、握手耗时、端点列表 |
| `/语音 帮助` | 帮助 |

别名：`/tts`、`/语音合成`、`/朗读`、`/cosyvoice` 与 `/语音` 等价。

**方言名认得多宽**：规范名（`四川`）、带后缀（`四川话`、`四川方言`）、地区别名（`成都话`、`重庆话`、`川渝`、`西南官话`）都能认，一共 40 多个词。认不出时会回一份可用列表，不会瞎猜。

## 3. 它是怎么工作的

```
用户发语音 ──► Record.convert_to_file_path()   拿到本地 wav
                │
                ├─ normalize()  不足 16k 补采样 / 双声道合单声道 / 超 30s 截断
                ├─ /prompt_wav_recognition  识别参考文字（约 1.2s）
                └─ 落盘 voices/<会话哈希>.wav + .json，首个音色顺手设为全局默认

/语音 文本 ──► 方言表 → instruct「用四川话说这句话。」
                │
                ├─ /upload        把参考音频传到创空间
                ├─ /queue/join    提交任务 {data, fn_index, session_hash}
                ├─ /queue/data    SSE 流，按 event_id 等 process_completed
                └─ file=<path>    下载 24kHz wav → concat → 语音消息
```

其中 `fn_index` 是运行时从 `/config` 的 `dependencies` 里按 `api_name` 反查的，不是写死的常量——创空间改了端点顺序也不会错位。

### 为什么不用 `gradio_client`

官方文档给的写法是 `gradio_client.Client(...)`，但这个插件没用它，原因有三个：

1. 它是**同步阻塞**实现，在协程里要么阻塞事件循环，要么额外开线程池；
2. 清华 PyPI 镜像里**没有** `gradio-client` 这个包（实测 `pip download` 直接 `No matching distribution`），插件依赖会装不上；
3. ModelScope 的 acw 网关**按 User-Agent 拦人**，非浏览器 UA 连 `/config` 都返回 403——`gradio_client` 报 `Could not fetch config` 就是这个原因，得自己控制请求头。

所以这里直接实现 Gradio 4.x 的队列协议，只依赖 aiohttp。代价是与 Gradio 大版本绑定（当前对 4.31.3 实测通过），收益是没有依赖、全异步、能并发、能自己控制超时与重试。

## 4. 方言表

| 方言 | 地区 | 交给模型的指令 | 一句提示 |
|---|---|---|---|
| 广东 | 粤语（广州话） | 用粤语说这句话。 | 和普通话差异最大，参考音越标准切换越稳 |
| 闽南 | 闽南语（泉州—厦门腔） | 用闽南话说这句话。 | 文白异读多，长句容易被拉回普通话 |
| 四川 | 西南官话（成渝片） | 用四川话说这句话。 | 重庆话、成都话都归这里，可补「重庆口音」 |
| 东北 | 东北官话 | 用东北话说这句话。 | 语调起伏大，情绪类台词辨识度最高 |
| 陕西 | 中原官话（关中片） | 用陕西话说这句话。 | 西安腔为准，陕北话属晋语不在此范围 |
| 山西 | 晋语（并州片） | 用山西话说这句话。 | 入声保留，慢速台词更像 |
| 上海 | 吴语（太湖片） | 用上海话说这句话。 | 浊音多，参考音是女声时更稳 |
| 天津 | 冀鲁官话（天津小片） | 用天津话说这句话。 | 相声腔和日常腔差别不小，可补「别太夸张」 |
| 山东 | 冀鲁／胶辽官话 | 用山东话说这句话。 | 默认按济南腔 |
| 宁夏 | 兰银官话（银吴片） | 用宁夏话说这句话。 | 与甘肃话差别很小 |
| 甘肃 | 兰银官话（金城片） | 用甘肃话说这句话。 | 兰州腔为准 |

指令句式和创空间输入框里的示例（「请输入instruct文本.例如:用四川话说这句话。」）保持一致，没有自己发明说法。**音色不在这里管**：instruct 只决定「怎么说」，参考音频才决定「谁在说」。

附加修饰拼在方言后面：

```
/语音 指令 语速慢一点   →  用四川话说这句话，语速慢一点。
只给修饰不给方言         →  语速慢一点。
两者都没有               →  （空串，等同纯音色复刻）
```

## 5. 参考音色的规则

| 项目 | 要求 | 插件怎么处理 |
|---|---|---|
| 长度 | 3–10 秒最好，上限 30 秒 | 不足 0.8 秒直接拒绝；超过 30 秒截断尾部 |
| 采样率 | 不低于 16 kHz | 低于 16k 用线性插值补到 16k（升采样不混叠） |
| 声道 | 单声道 | 双声道取均值合成 |
| 位深 | 16bit PCM | 其他位深交给 ffmpeg；没有 ffmpeg 就明确报错 |
| 内容 | 一句完整、干净的话 | 缺参考文字时用 SenseVoice 自动识别 |

**截断后才会识别**——所以参考文字和实际音频永远对得上，复刻模式不会因为「文字比音频多一句」而跑偏。

音色按会话（`unified_msg_origin`）保存，互不干扰：

```
data/plugin_data/astrbot_plugin_cosyvoice_tts/
├── voices/<会话哈希>.wav     规整后的参考音频
├── voices/<会话哈希>.json    {name, prompt_text, seconds, sample_rate, created}
├── voices/_default.*         全局默认音色（原生 TTS 用）
├── prefs.json                会话偏好：方言、自定义指令
└── tmp/                      处理中的中间文件
```

**几个刻意的取舍**：

- **第一个音色会自动成为全局默认**。这样原生 TTS Provider 不用额外配置就可用。
- **已有音色时，日常发的语音不会覆盖它**。否则你把机器人当聊天对象发语音，音色会被反复重置。要换就说 `/语音 音色 换`，再说一段语音。
- **带文字的消息不当作「设音色」**。避免误判。

## 6. 接成原生 TTS（让回复自动带语音）

插件注册了一个类型为 `cosyvoice2_modelscope`、显示名「CosyVoice2 方言 TTS」的 Provider。

1. WebUI → 配置 → 服务提供商 → 新增，类型里选 **CosyVoice2 方言 TTS**；
2. 填两个东西：
   - `ref_wav`：参考音频的绝对路径（留空则用 `voices/_default.wav`，也就是第一个上传的音色或 `/语音 音色 全局` 设的那个）
   - `dialect`：默认方言，如 `四川`
3. 打开会话的语音回复（或 `/tts`），之后机器人的回复就会被朗读。

Provider 的 `get_audio(text)` 拿不到会话上下文，所以它只能用**一份全局音色**——想让每个会话用自己的音色，就用 `/语音` 指令，别用 Provider。两条路可以同时开着。

`register_provider` 配置项关掉后，插件不会注册 Provider，只保留指令。万一 AstrBot 某天改了 Provider 接口，指令侧也不会跟着坏——注册失败只记一条 warning。

## 7. 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `commands_enabled` | `true` | `/语音` 指令总开关 |
| `api_base` | `https://iic-cosyvoice2-0-5b.ms.show/` | 应用地址，可换自己部署的同款 Gradio 应用 |
| `mode` | `自然语言控制` | 默认推理模式；`3s极速复刻` 需要参考文字 |
| `default_dialect` | 空 | 新会话默认方言，留空=标准话 |
| `default_instruct` | 空 | 默认附加修饰 |
| `auto_bind_voice` | `true` | 会话没音色时，收到的第一条纯语音自动记成音色 |
| `auto_rebind` | `false` | 已有音色也接受新语音替换（默认关，防误覆盖） |
| `auto_recognize` | `true` | 自动识别参考文字 |
| `register_provider` | `true` | 注册原生 TTS Provider |
| `timeout` | `180` | 单次合成超时（秒） |
| `concurrency` | `2` | 并发上限。公开创空间是共享队列，开大只会一起排队 |
| `retries` | `2` | 排队满（503）或连接抖动时的重试次数，指数退避 |
| `debug` | `false` | 打印上传路径、任务号等细节 |

## 8. 实测数据

以下都是在本机（Windows，ModelScope 公开创空间，2026-10）跑出来的真实数字，不是估算。

**11 种方言各合成一句**（参考音频 6.0 秒 / 22.05 kHz，各自方言的示例台词）：

| 方言 | 耗时 | 输出时长 | 方言 | 耗时 | 输出时长 |
|---|---|---|---|---|---|
| 广东 | 4.1s | 3.44s | 天津 | 8.2s | 4.60s |
| 闽南 | 7.0s | 4.28s | 山东 | 6.8s | 3.28s |
| 四川 | 4.2s | 3.44s | 宁夏 | 6.7s | 2.68s |
| 东北 | 8.1s | 5.64s | 甘肃 | 6.3s | 3.16s |
| 陕西 | 7.3s | 4.48s | 山西 | 6.8s | 4.08s |
| 上海 | 7.4s | 5.20s | | | |

- 11/11 全部成功，串行总耗时 73 秒，平均 6.6 秒/句。
- 输出统一 24 kHz 单声道 wav。**输出时长随方言变化**（2.68–5.64 秒），说明 instruct 确实改变了韵律，而不是被忽略。
- 握手（取 `/config`）0.3 秒，之后有 10 分钟缓存。

**其它路径**：

| 项目 | 结果 |
|---|---|
| 参考文字识别 | 1.2–1.3 秒，中文准确 |
| 3s 极速复刻 | 6.8 秒出音（4.1 秒音频） |
| 原生 TTS Provider | 7.5 秒出音（含「粤语 + 语气活泼一点」指令） |
| 长文本（2400 字） | 切 4 段、串行合成后拼接成一条语音消息 |
| 超限文本（2700 字） | 直接拒绝并提示分段，不会硬跑两分钟 |

**关于方言像不像**：这件事只能靠耳朵判断。插件能保证的是指令正确送达、音色正确、不同方言产出不同音频；具体口音的地道程度取决于模型本身与参考音频，尤其粤语、闽南语这类与普通话差距大的方言，短句比长句稳。

## 9. 已知限制

1. **依赖公开创空间**。对方排队、限流、休眠、改接口都会直接影响本插件。创空间冷启动时首句可能要等十几秒；被重启时任务会中断，插件会重试，仍失败则回一条文字说明。
2. **不保证方言地道**。模型对 11 种方言的支持程度不一样；参考音频口音重、或句子太长时，模型可能滑回普通话。可以先 `/语音 示例` 试一句。
3. **必须有参考音频才能出声**。这是刻意的设计：没有参考音频时 clone 出来的音色随机，不如不给。
4. **参考音频要先转成 wav**。入站语音由 AstrBot 的 `convert_to_file_path()` 转好，这条路没问题；但如果你在配置里直接填 `ref_wav` 指向 mp3/m4a，需要本机有 ffmpeg。
5. **自然语言控制模式下参考文字可选**。复刻模式必须有，且要和音频内容一致——不一致会让韵律跑偏。
6. **Provider 只能用全局音色**。`get_audio(text)` 没有会话信息，做不到「每个群一个音色」。
7. **当前文本上限 600 字/段、最多 4 段**（共 2400 字）。再多会被拒绝，避免一句话卡住几十秒。
8. **没有流式**。创空间的 `stream` 参数在当前接口里只接受 `"False"`，出音要等整句合成完。
9. **`ms.show` 域名需要浏览器 UA**。已内置；如果你改用自己的部署后又遇到 403，多半是网关按 UA 拦了。

```bash
python tools/try_dialects.py --check                          # 只探活
python tools/try_dialects.py --ref 你的参考音.wav              # 11 种方言各合成一遍 → out/
python tools/try_dialects.py --ref ref.wav --dialect 四川 广东   # 只跑两种

python demo.py --ref ref.wav --dialect 粤语                     # 演示 + 真合成
```

## 12. 声明

- 本插件不含模型权重，合成请求转发到 ModelScope 公开创空间；模型的许可证与可用性由上游决定。
- **参考音色请只使用你本人，或已获明确授权的声音。** 用他人声音合成未授权内容可能侵犯声音权/人格权，也可能违反平台规则。
- 请勿用于冒充他人、诈骗、伪造证据或其他误导性用途。
- 方言转写由模型决定，不保证与真实方言一致，请自行判断合成结果是否适合公开发布。
